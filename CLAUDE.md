# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

CourseSelect is a PyQt5 desktop application that automates course selection (选课) for DHU's (东华大学) educational administration system (jwgl.dhu.edu.cn). It supports concurrent multi-course selection, "pick-up" mode (monitoring for vacancies), course "upgrade" (auto-drop then select a better class), scheduled auto-start, captcha handling via popup dialog, and WeChat push notifications.

## Architecture

### Source Files

| File | Role |
|---|---|
| `main.py` | Entry point — sets up timestamped logging to `CoureseSelectDebug.log`, global exception hook (`sys.excepthook`), wraps stdout/stderr with timestamps, then launches `ProductionGlassmorphismUI` |
| `modern_ui_production.py` | Single-file UI (~1945 lines) containing the main window (`ProductionGlassmorphismUI`), all dialogs (`StyledInputDialog`, `CaptchaDialog`, `SelectAccountsDialog`, `SelectCoursesDialog`), and all worker threads (`SingleCourseWorker`, `PickUpWorker`, `UpgradeWorker`, `PreWorkThread`) |
| `core.py` | Business logic: cookie acquisition (CAS HTTP + RSA — no browser), course selection/cancellation (via `requests` `_requests_post()` helper backed by a thread-local connection-pooled session), JSON file I/O, PushPlus notifications. **Note: contains duplicate function definitions** — see below |
| `fetch_courses.py` | Standalone CLI script to scrape all course offerings from the academic system into `courses_full.json` (used by pick-up and upgrade modes) |
| `test.py` | Standalone test script for PushPlus push notification |
| `CourseSelect.spec` | PyInstaller config for building `CourseSelect.exe` (onefile + windowed) |
| `CourseSelect.ifp` | InstallForge installer project for distributing the built exe |

**Known dead code in `core.py`:** Functions `query_course_info`, `cancelSC`, and `sccourse` each appear twice — first as curl-subprocess implementations, then as `requests`-based versions that overwrite the first definition. Only the second (`_requests_post`-based) definitions are live. The curl code is dead but still present in the file.

### Data Files

All stored as JSON in the repo root:

- `accounts.json` — `{"accounts": [{"name": "显示名", "username": "学号", "password": "密码"}]}`
- `courses.json` — `{"用户名": ["courseId1", "courseId2"]}` — courses (cttIds) to select for each user
- `cookies.json` — `{"用户名": "cookie_string"}` — persisted session cookies (gitignored)
- `delete_courses.json` — `{"用户名": [{"courseCode": "...", "classNo": "..."}]}` — courses to drop before selecting
- `settings.json` — `{"push_token": "..."}` — PushPlus token
- `courses_full.json` — Full course catalog with timetables, generated by `fetch_courses.py`. Maps `cttId` → `kcbh` (course code), used by pick-up and upgrade modes

### Key Dependencies

- **PyQt5** — GUI framework
- **requests** — all HTTP API calls (`_requests_post` wrapper in core.py) and CAS login
- **cryptography** — RSA PKCS1v15 password encryption for CAS login (`_rsa_encrypt_password` in core.py)
- **curl** (subprocess) — only used by `fetch_courses.py` (data scraping), NOT by core selection logic
- **BeautifulSoup4** — HTML parsing in `fetch_courses.py` (timetable extraction)
- **PushPlus** (`pushplus.plus`) — WeChat push notification (via `urllib.request`)

*No Selenium / msedgedriver / Chrome portable required at runtime — login is pure HTTP.*

### Worker Types

1. **`SingleCourseWorker`** — One per course in normal selection mode. Polls `scSubmit` with jittered intervals. On success, removes course from `courses.json` via `QMutex`-protected file write and sends WeChat push.
2. **`PickUpWorker`** (捡漏) — One per course code in pick-up mode. Runs `accessJudge` → `initACC` loop checking `enrollCnt < maxCnt`; calls `scSubmit` when a vacancy appears. Staggered 500ms between worker starts. Uses `courses_full.json` to find `cttId` → `kcbh` mapping.
3. **`UpgradeWorker`** (升级课程) — Monitors a target course while holding a current course. On vacancy: calls `cancelSC` on current course → `scSubmit` on target. Skips `accessJudge` since owning an enrolled course makes it fail.
4. **`PreWorkThread`** — Phase 1 of start flow. Iterates `delete_courses.json` entries, calls `cancelSC` for each, then triggers `launch_concurrent_workers`.

### Dialog Types

- **`StyledInputDialog`** — Themed single/multi-line text input with dark/light mode support.
- **`CaptchaDialog`** — Fetches captcha image from `jwgl.dhu.edu.cn/dhu/captcha/code`, displays it, lets user type the code. Used when `sccourse` returns `msg == "F"` (captcha required). Worker blocks on a `threading.Event` with 120s timeout. Fallback: uses `"1234"` as default code on cancel/timeout.
- **`SelectAccountsDialog`** — Multi-select checkbox list of accounts for batch cookie updates.
- **`SelectCoursesDialog`** — Multi-select checkbox list of courses (grouped by `kcbh`) for pick-up mode launch.

## Core Workflows

### Cookie Acquisition (`core.get_cookies`)

Pure HTTP CAS login + RSA — no browser is launched. Mirrors DLSF's `app.js loginGetToken`:

1. `GET cas.dhu.edu.cn/esc-sso/authn/policy` → fetch RSA public key + `publicKeyId`
2. PKCS1v15-encrypt the password with `cryptography.hazmat.primitives.asymmetric.padding`
3. `POST /esc-sso/authn/login` → CAS-domain session cookie
4. `GET /esc-sso/login?service=jwgl/...` → expects 302 with ticket URL in `Location`
5. `GET <ticket URL>` → extract `JSESSIONID` + `newjwgl` via `_extract_jwgl_cookies` (uses `response.raw.headers.getlist("Set-Cookie")` to handle multiple Set-Cookie headers; falls back to regex over the merged header)

Returns `[{"name":"JSESSIONID","value":"..."},{"name":"newjwgl","value":"..."}]`. The caller serializes to a `"k=v; k=v"` string and stores in `cookies.json`. The `browser_type=` kwarg is deprecated and ignored — kept only for call-site compatibility.

### Course Selection API (all via `_requests_post()` helper in core.py)

- **accessJudge** (POST) — permission check before querying course sections
- **initACC** (POST) — query available class sections via DataTables-style params
- **scSubmit** (POST) — submit selection for a specific `cttId` (class section ID). Accepts optional `capCode` param for captcha bypass
- **cancelSC** (POST) — drop a course by `courseCode` + `classNo`

Requests meticulously replicate browser headers (User-Agent, Referer, sec-ch-ua, cookies) to avoid anti-bot detection.

### Captcha Handling Flow

1. `sccourse` returns JSON with `"msg": "F"` → worker emits `captcha_signal`
2. UI shows `CaptchaDialog` which fetches captcha image from the server
3. User types the code and clicks OK → worker's `captcha_event` is set
4. Worker retries `sccourse` with `capCode=<user_input>`
5. If dialog is cancelled or times out (120s), fallback code `"1234"` is used

### Selection Flow (Normal Mode)

1. User clicks "开始并发选课" → `toggle_selection()` → `start_selection()`
2. **Phase 1** (`PreWorkThread`): Process `delete_courses.json` — drop courses via `cancelSC`
3. **Phase 2** (`launch_concurrent_workers`): Fire concurrent `SingleCourseWorker`s, one per course ID in `courses.json`
4. Workers poll `scSubmit` with random jitter (±60% of interval). On success: remove from `courses.json`

### Anti-Bot Measures (built-in)

- Random jitter (±60% of interval) between requests, staggered 100ms between worker starts
- Soft-ban detection: if response is empty or contains captcha indicators (`"F"` / `"Empty"`), backs off 10-20s after 3 consecutive hits (`handle_soft_ban`)
- Workers check `is_running` flag on each loop iteration for clean stop

### Scheduling

- `QTimer` ticks every second, checks `QTime.currentTime()` against user-set `HH:mm:ss` target
- On match, auto-fires `toggle_selection()`. Clears `scheduled_time` after firing (one-shot)

## Key Commands

### Development
```bash
pip install -r requirements.txt    # install dependencies
python main.py                      # run the application
python test.py                      # test PushPlus notification
```

### Course Data Scraping (for pick-up & upgrade modes)
```bash
python fetch_courses.py                         # scrape all courses (uses first valid cookie user)
python fetch_courses.py --user "张三"            # specify user
python fetch_courses.py --term 88               # specify term ID (default 88)
python fetch_courses.py --limit 10              # test with first 10 courses
python fetch_courses.py --list-only             # skip timetable details
python fetch_courses.py --output courses_full.json
```

### Build (Windows .exe)
```bash
pip install pyinstaller              # if not already installed
pyinstaller CourseSelect.spec        # builds dist/CourseSelect/CourseSelect.exe
```
**Post-build:** The `.spec` is onefile + windowed config. An InstallForge project (`CourseSelect.ifp`) packages the dist into a distributable installer. No external binaries to copy — login is pure HTTP, so `msedgedriver.exe` and the `chrome/` directory are no longer needed at runtime.

### Debugging
- All stdout/stderr + core module logs go to `CoureseSelectDebug.log` with timestamps
- `core.get_cookies()` accepts `report_callback=` to pipe CAS login progress to the UI log
- Test core I/O: `python -c "from core import load_accounts, load_courses; print(load_accounts(), load_courses())"`

## Important Patterns

- **Thread-safe file I/O**: All worker threads guard JSON file writes with a global `QMutex` (`file_lock` in `modern_ui_production.py`) to prevent corruption from concurrent workers
- **Worker-to-UI communication**: Exclusively via `pyqtSignal` (`log_signal`, `success_signal`, `finished_signal`, `captcha_signal`). No direct UI access from threads
- **Worker lifecycle**: Workers have an `is_running` flag checked in the loop. Stop calls `.stop()` then `.wait()` to join. Workers are collected in `self.workers` (concurrent selection), `self.pickup_workers` (pick-up mode), `self.upgrade_workers` (upgrade mode) lists
- **Result parsing**: All API calls return raw strings. Success determined by: `json.loads()` checking `"success": true` and `"msg" != "F"`, OR string matching for `"true"` / absent `"Empty"` / absent `"F"`. Empty response triggers soft-ban backoff
- **UI theming**: Dark/light toggle via `apply_glassmorphism_style()` rebuilds the full QSS stylesheet from a colors dict. Colors use indigo/purple for dark mode, blue for light mode
- **`_requests_post` wrapper**: Centralized POST helper at the top of `core.py` that injects all anti-bot headers. Used by all selection API functions. Returns raw response string, `"TIMEOUT"` on timeout, or `""` on exception
- **Thread-local HTTP session pool**: `core._get_session()` lazily builds one `requests.Session` per worker thread, with `HTTPAdapter(pool_connections=10, pool_maxsize=20)` and the static anti-bot headers pre-set. `_requests_post` reuses this rather than rebuilding a request each call — keep-alive matters under jittered concurrent polling
- **Base path resolution**: `main.py` and `core.py` both check `getattr(sys, 'frozen', False)` to determine whether to resolve paths relative to `sys.executable` or `__file__`. This supports both development and PyInstaller-packaged execution
- **Stop-all button**: `toggle_selection()` acts as unified stop for all modes — clears workers, pickup_workers, AND upgrade_workers. The `is_running` flag and worker list clearing prevent stale workers from lingering
