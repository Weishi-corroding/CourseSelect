# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

CourseSelect is a PyQt5 desktop application that automates course selection (选课) for DHU's (东华大学) educational administration system (jwgl.dhu.edu.cn). It supports concurrent multi-course selection, "pick-up" mode (monitoring for vacancies), scheduled auto-start, and WeChat push notifications.

## Architecture

### Source Files

| File | Role |
|---|---|
| `main.py` | Entry point — sets up timestamped logging to `CoureseSelectDebug.log`, global exception hook (`sys.excepthook`), wraps stdout/stderr with timestamps, then launches `ProductionGlassmorphismUI` |
| `modern_ui_production.py` | Single-file UI (~920 lines) containing the main window (`ProductionGlassmorphismUI`), all dialogs (`StyledInputDialog`), and all worker threads (`SingleCourseWorker`, `PickUpWorker`, `PreWorkThread`) |
| `core.py` | Business logic: cookie acquisition (Selenium), course selection/cancellation (via `requests`), JSON file I/O, PushPlus notifications. **Note: contains duplicate function definitions** (see below) |
| `fetch_courses.py` | Standalone CLI script to scrape all course offerings from the academic system into `courses_full.json` (used by pick-up mode) |
| `test.py` | Standalone test script for PushPlus push notification |
| `CourseSelect.spec` | PyInstaller config for building `CourseSelect.exe` (onefile + windowed) |
| `CourseSelect.ifp` | InstallForge installer project for distributing the built exe |

**Known dead code in `core.py`:** Functions `query_course_info`, `cancelSC`, and `sccourse` each appear twice — first as curl-subprocess implementations, then as `requests`-based versions that overwrite the first definition. Only the second (`_requests_post`-based) definitions are live. The curl code is dead but still present in the file.

### Data Files

All stored as JSON in the repo root:

- `accounts.json` — `{"accounts": [{"name": "显示名", "username": "学号", "password": "密码"}]}`
- `courses.json` — `{"用户名": ["courseId1", "courseId2"]}` — courses to select for each user
- `cookies.json` — `{"用户名": "cookie_string"}` — persisted session cookies (gitignored)
- `delete_courses.json` — `{"用户名": [{"courseCode": "...", "classNo": "..."}]}` — courses to drop before selecting
- `settings.json` — `{"push_token": "..."}` — PushPlus token
- `courses_full.json` — Full course catalog with timetables, generated by `fetch_courses.py`. Maps `cttId` → `kcbh` (course code), used exclusively by pick-up mode

### Key Dependencies

- **PyQt5** — GUI framework
- **Selenium** — browser automation for login cookie acquisition
- **requests** — all HTTP API calls (`_requests_post` wrapper in core.py)
- **curl** (subprocess) — only used by `fetch_courses.py` (data scraping), NOT by core selection logic
- **BeautifulSoup4** — HTML parsing in `fetch_courses.py` (timetable extraction)
- **PushPlus** (`pushplus.plus`) — WeChat push notification (via `urllib.request`)
- **msedgedriver.exe** — required alongside the app for Edge automation

## Core Workflows

### Cookie Acquisition (`core.get_cookies`)
1. Launches Edge (or Chrome Portable from `./chrome/`) via Selenium
2. Navigates to `jwgl.dhu.edu.cn/dhu/casLogin`, fills username/password, clicks login
3. Polls cookies until `JSESSIONID` or `newjwgl` appears (30s timeout)
4. Returns cookie list; caller serializes to string and stores in `cookies.json`

### Course Selection API (all via `_requests_post()` helper in core.py)

- **accessJudge** (POST) — permission check before querying course sections
- **initACC** (POST) — query available class sections via DataTables-style params
- **scSubmit** (POST) — submit selection for a specific `cttId` (class section ID)
- **cancelSC** (POST) — drop a course by `courseCode` + `classNo`

Requests meticulously replicate browser headers (User-Agent, Referer, sec-ch-ua, cookies) to avoid anti-bot detection.

### Selection Strategies

1. **Two-Phase Start Flow** — When "start" is clicked:
   - Phase 1 (`PreWorkThread`): Process `delete_courses.json` — drop courses via `cancelSC` before attempting to select new ones
   - Phase 2 (`SingleCourseWorker` per course): Fire concurrent workers, each polling `scSubmit` with jittered intervals. On success, course is removed from `courses.json` via `QMutex`-protected file write

2. **Pick-Up Mode** (捡漏) — `PickUpWorker` continuously runs `accessJudge` → `initACC` → checks `enrollCnt < maxCnt` → calls `scSubmit` when a vacancy appears. Uses `courses_full.json` to map `cttId` → `kcbh` (course code). Staggered 500ms between worker starts to avoid batch detection.

### Anti-Bot Measures (built-in)

- Random jitter (±60% of interval) between requests
- Soft-ban detection: if response is empty or contains captcha indicators (`"F"` / `"Empty"`), backs off 10-20s after 3 consecutive hits
- Selenium uses `--disable-blink-features=AutomationControlled` (no `excludeSwitches` — it causes crashes on Chromium 149+)

### Scheduling

- `QTimer` ticks every second, checks `QTime.currentTime()` against user-set `HH:mm:ss` target
- On match, auto-fires `toggle_selection()`

## Key Commands

### Development
```bash
pip install -r requirements.txt    # install dependencies
python main.py                      # run the application
python test.py                      # test PushPlus notification
```

### Course Data Scraping (for pick-up mode)
```bash
python fetch_courses.py                         # scrape all courses (uses first valid cookie user)
python fetch_courses.py --user "张三"            # specify user
python fetch_courses.py --term 88               # specify term ID (default 88)
python fetch_courses.py --limit 10              # test with first 10 courses
python fetch_courses.py --list-only             # skip timetable details
python fetch_courses.py --output courses_full.json
```

### Build (Windows .exe)
```bash
pyinstaller CourseSelect.spec       # builds dist/CourseSelect/CourseSelect.exe
```
**Note:** The .spec file does not auto-include `msedgedriver.exe` or the `chrome/` directory. These must be copied to the dist folder manually after build.

### Debugging
- All stdout/stderr + core module logs go to `CoureseSelectDebug.log` with timestamps
- `core.get_cookies()` accepts `report_callback=` to pipe Selenium progress to the UI log
- Test core I/O: `python -c "from core import load_accounts, load_courses; print(load_accounts(), load_courses())"`

## Browser Setup

- **Edge** (default): Uses system-installed Edge with bundled `msedgedriver.exe`. Driver version must match installed Edge version.
- **Chrome Portable**: Expects `chrome/chrome.exe` and `chrome/chromedriver.exe` in the app directory. Manually downloaded Chrome portable + matching chromedriver.

## Important Patterns

- **Thread-safe file I/O**: All worker threads guard JSON file writes with a global `QMutex` (`file_lock` in `modern_ui_production.py`) to prevent corruption from concurrent workers
- **Worker-to-UI communication**: Exclusively via `pyqtSignal` (`log_signal`, `success_signal`, `finished_signal`). No direct UI access from threads
- **Worker lifecycle**: Workers have an `is_running` flag checked in the loop. Stop calls `.stop()` then `.wait()` to join. Workers are collected in `self.workers` (concurrent) and `self.pickup_workers` (pick-up mode) lists
- **Result parsing**: All API calls return raw strings. Success determined by: `json.loads()` checking `"success": true` and `"msg" != "F"`, OR string matching for `"true"` / absent `"Empty"` / absent `"F"`
- **UI theming**: Dark/light toggle via `apply_glassmorphism_style()` rebuilds the full QSS stylesheet from a colors dict. Toggle updates button, card, menu, list, and tab styling
- **`_requests_post` wrapper**: Centralized POST helper at the top of `core.py` that injects all anti-bot headers. Used by all selection API functions. Returns raw response string, `"TIMEOUT"` on timeout, or `""` on exception
- **Base path resolution**: `main.py` and `core.py` both check `getattr(sys, 'frozen', False)` to determine whether to resolve paths relative to `sys.executable` or `__file__`. This supports both development and PyInstaller-packaged execution
- **`.gitignore`**: Only ignores `cookies.json`
